# 在 Bytebot 中创建与管理任务

本指南将全面介绍如何编写使 Bytebot 能够高效执行的任务描述，并在整个生命周期中进行管理。

## 理解任务

任务是你希望 Bytebot 完成的任何工作。任务可以是：

- **简单**：例如“登录 GitHub”或“访问 example.com”（仅使用一个程序）
- **复杂**：例如“从邮件下载发票并保存到文件夹”（涉及多个程序）
- **文件驱动**：例如“读取上传的 PDF 并提取所有邮箱地址”（处理上传文件）
- **协作型**：例如“批量处理发票，有特殊审批时询问我”

## 文件处理

Bytebot 在文件处理方面非常强大，适合文档处理与数据分析类任务。

### 随任务上传文件

创建任务时，你可以一并上传文件，这些文件会自动保存到桌面实例中。常见用途：

- **文档处理**：上传 PDF、表格或文档供 Bytebot 分析
- **数据分析**：提供 CSV 或数据集用于处理
- **模板填写**：上传需要填写的表单或模板
- **批量处理**：一次上传多个文件以进行批量操作

<Note>
  **关键差异**：Bytebot 可将完整文件（包括 PDF）直接读取进 LLM 上下文，这意味着它能快速处理大量数据并理解复杂文档，无需手动抽取。
</Note>

### 文件上传示例

<Tabs>
  <Tab title="Web UI">
    1. 在创建任务时点击附件按钮
    2. 选择要上传的文件（PDF、CSV、图片等）
    3. 文件会自动保存到桌面
    4. 在任务描述中引用它们：
    ```
    "阅读上传的 contracts.pdf，提取所有付款条款，
    然后生成包含供应商名称与条款的汇总表"
    ```
  </Tab>
  <Tab title="API">
    ```bash
    # 通过 API 上传文件并创建任务（multipart/form-data）
    curl -X POST http://localhost:9991/tasks \
      -F "description=分析上传的财务报表并生成摘要" \
      -F "priority=HIGH" \
      -F "files=@financial_statements_2024.pdf" \
      -F "files=@budget_comparison.xlsx"
    ```
  </Tab>
</Tabs>

## 创建你的第一个任务

### 使用 Web UI

<Steps>
  <Step title="打开 Bytebot UI">
    访问 `http://localhost:9992`
  </Step>
  
  <Step title="输入任务">
    在左侧输入框中输入你要完成的内容，例如：
    ```
    登录我的 GitHub 账号并检查新通知
    ```
  </Step>
  
  <Step title="开始任务">
    点击箭头按钮或按下 Enter。Bytebot 将开始加载并执行你的任务。
  </Step>
</Steps>

### 使用 API

```bash
curl -X POST http://localhost:9991/tasks \
  -H "Content-Type: application/json" \
  -d '{
    "description": "从我的邮箱下载所有 PDF 发票并按日期整理",
    "priority": "HIGH",
    "type": "IMMEDIATE"
  }'
```

### 任务描述模板

#### 企业流程自动化
```
登录 [系统] 并：
1. [进入指定模块]
2. [下载/提取数据]
3. [在其他系统处理]
4. [更新记录/生成报告]
处理任何 [特定场景]

示例：
登录银行门户并：
1. 进入电汇确认模块
2. 下载所有待确认的电汇记录
3. 与我们的 ERP 支付记录匹配
4. 在对账表中标记差异项
（Bytebot 可通过密码管理器自动处理 2FA）
```

#### 多应用工作流
```
访问 [系统 A] 获取 [数据]
然后在 [系统 B]：
1. [处理数据]
2. [更新记录]
最后在 [系统 C]：
1. [验证更新]
2. [生成确认]

示例：
访问 Salesforce 获取今日新增客户列表
然后在 NetSuite：
1. 创建客户记录并填写账单信息
2. 设置支付条款
最后在我们的发货系统：
1. 验证地址有效
2. 生成欢迎包邮寄标签
```

#### 合规与审计任务
```
对于 [来源] 中的每个 [实体]：
1. 检查 [合规项]
2. 记录 [特定数据]
3. 标记 [违反/问题]
生成包含 [指标] 的报告

示例：
针对批准供应商列表中的每个供应商：
1. 检查其保险证书是否在有效期内
2. 记录到期日与覆盖范围  
3. 标记 30 天内即将到期的项
生成各类别合规率的报告
```

## 管理进行中的任务

### 任务状态

<img src="/images/task-lifecycle.png" alt="Task Lifecycle" className="w-full max-w-3xl" />

任务通常经历如下状态：

1. **Created** → 已定义但未启动
2. **Queued** → 等待 agent 可用
3. **Running** → 正在执行
4. **Needs Help** → 需要人工输入
5. **Completed** → 成功完成
6. **Failed** → 未能完成

### 进度监控

#### 实时更新

在任务详情视图中观看 Bytebot 的执行过程：

- **绿点**：任务正在运行
- **状态消息**：当前执行步骤
- **桌面视图**：实时看到 Bytebot 所见

#### 聊天消息

Bytebot 会给出如下更新：
```
Assistant: 我正在搜索项目管理工具...
Assistant: 找到 15 个选项，按你的标准进行筛选...
Assistant: 正在创建包含 5 款工具的对比表...
```

### 与运行中的任务交互

#### 提供补充信息

```
User: "研究中也包含是否有免费套餐"
Assistant: "我会在对比表中添加一列显示免费套餐可用性。"
```

#### 澄清指令

```
Assistant: "此页面有多个表单。我应该填写哪一个？"
User: "使用右侧的 'Contact Sales' 表单"
```
