# 接管模式：人机协作

接管模式允许你在需要时接管桌面，帮助 Bytebot。使用方式有两种：

## 1. 任务执行期间
在任务详情视图中，你可以点击接管按钮以：
- 当 Agent 走错方向时进行中断
- 引导其朝正确方案前进
- 在遇到障碍时进行人工处理

## 2. 自动触发
当任务状态变为 "needs help"（需要帮助）时，接管模式会自动启用——这表示 Agent 意识到它无法独立完成。

## 操作如何被记录
在接管期间，你的所有操作（点击、拖拽、滚动、输入、按键）都会记录到与 Agent 相同的统一动作空间中。这意味着 Bytebot 能理解并从你的操作中学习。

## 桌面标签用于设置

在任务之外，主页面提供独立的 **Desktop** 标签：
- 可自由访问桌面
- 此模式下不会记录任何操作
- 适用于：
  - 安装程序
  - 登录应用或网站
  - 设置桌面环境
  - 进行通用维护

## 启用接管模式

### 方法一：任务中手动接管

<Steps>
  <Step title="打开任务详情视图">
    当 Bytebot 在执行任务时，点击该任务以打开详情视图。
  </Step>
  
  <Step title="点击接管按钮">
    点击接管按钮以中断 Agent 并取得控制权。
  </Step>
  
  <Step title="引导 Bytebot">
    执行必要操作以跨越障碍或展示正确路径。
  </Step>
  
  <Step title="释放控制">
    点击释放控制，让 Bytebot 从你离开的地方继续执行。
  </Step>
</Steps>

### 方法二：在需要帮助时自动启用

当 Bytebot 将任务状态设为 "needs help" 时：
- 接管模式会自动启用
- 你将看到需要协助的通知
- 接管控制以协助解决问题
- 释放控制后，Bytebot 将继续执行

## 常见用例

### 1. 复杂 UI 导航

<Card title="自研或复杂应用" icon="window">
  **场景**：使用专有或复杂软件
  
  **步骤**：
  1. 让 Bytebot 打开应用
  2. 接管以导航复杂界面
  3. 使用聊天说明你的操作
  4. 归还控制让 Bytebot 继续
  
  **示例**："打开我们的内部 CRM，我来演示如何进入报表模块"
</Card>

### 2. 错误恢复

<Card title="处理突发情况" icon="exclamation-triangle">
  **场景**：Bytebot 遇到错误或卡住
  
  **步骤**：
  1. 发现 Bytebot 正在挣扎
  2. 接管以解决问题
  3. 引导其越过障碍
  4. 在聊天中说明问题原因
  5. 归还控制让 Bytebot 继续
  
  **示例**："让我处理这个阻塞流程的意外弹窗"
</Card>

### 3. 演示式教学

<Card title="以演示代替说明" icon="graduation-cap">
  **场景**：复杂的多步流程
  
  **步骤**：
  1. 在需要演示时接管
  2. 按正常速度完成任务（无需放慢）
  3. 使用聊天解释你点击的内容与原因
  4. 归还控制
  5. 让 Bytebot 复现该流程

</Card>

<Warning>
  **重要**：接管模式下每个动作都会截图。请勿输入不希望被截图记录的数据。
</Warning>

## 最佳实践

### 建议 ✅

- **接管时使用聊天**：输入消息解释你正在做什么以及原因
- **解释你的点击**：分享 UI 元素的上下文与用途
- **离开前归还控制**：离开任务详情前务必释放控制
- **测试理解**：让 Bytebot 总结它学到的内容

### 避免 ❌

- **输入敏感数据**：接管期间所有动作都会被截图
- **忽略聊天说明**：上下文有助于 Bytebot 学习模式
- **在控制中离开任务视图**：任务会停留在接管状态
- **假设它了解你的工作流**：请解释应用特定的流程

<Note>
  **无需放慢**：Bytebot 会在每个动作前后捕获状态，你可以按正常速度操作。
</Note>

## 总结

接管模式为你在需要时引导 Bytebot 或处理其无法独立解决的状况提供了灵活性。无论是导航复杂界面、从错误中恢复，还是教授新的工作流，接管模式都确保在需要时你能掌控一切。
