# 通过 Helm 在 Kubernetes 部署 Bytebot

Helm 为在 Kubernetes 集群中部署 Bytebot 提供了简便方式。

## 前置条件

- Kubernetes 集群（1.19+）
- 已安装 Helm 3.x
- 已配置 kubectl
- 集群可用内存至少 8GB

## 快速开始

<Steps>
  <Step title="克隆仓库">
    ```bash
    git clone https://github.com/bytebot-ai/bytebot.git
    cd bytebot
    ```
  </Step>
  
  <Step title="配置 API Key">
    创建 `values.yaml`（至少添加一个提供商的密钥）：
    
    ```yaml
    bytebot-agent:
      apiKeys:
        anthropic:
          value: "sk-ant-your-key-here"
        # 可选：添加更多提供商
        # openai:
        #   value: "sk-your-key-here"
        # gemini:
        #   value: "your-key-here"
    ```
  </Step>
  
  <Step title="安装 Bytebot">
    ```bash
    helm install bytebot ./helm \
      --namespace bytebot \
      --create-namespace \
      -f values.yaml
    ```
  </Step>
  
  <Step title="访问 Bytebot">
    ```bash
    # 本地端口转发
    kubectl port-forward -n bytebot svc/bytebot-ui 9992:9992
    
    # 打开 http://localhost:9992
    ```
  </Step>
</Steps>

## 基本配置

### API Key

配置至少一个 AI 提供商：

```yaml
bytebot-agent:
  apiKeys:
    anthropic:
      value: "sk-ant-your-key-here"
    openai:
      value: "sk-your-key-here"
    gemini:
      value: "your-key-here"
```

### 资源限制（可选）

根据需求调整资源：

```yaml
# Desktop 容器（执行自动化）
desktop:
  resources:
    requests:
      memory: "2Gi"
      cpu: "1"
    limits:
      memory: "4Gi"
      cpu: "2"

# Agent（AI 编排）
agent:
  resources:
    requests:
      memory: "1Gi"
      cpu: "500m"
```

### 外部访问（可选）

为域名访问启用 Ingress：

```yaml
ui:
  ingress:
    enabled: true
    hostname: bytebot.your-domain.com
    tls: true
```

## 访问方式

### 本地（推荐）

```bash
kubectl port-forward -n bytebot svc/bytebot-ui 9992:9992
```

访问：http://localhost:9992

### 外部访问

若已配置 Ingress：
- 访问：https://bytebot.your-domain.com

## 验证部署

检查所有 pod 运行状态：

```bash
kubectl get pods -n bytebot
```

期望输出：
```
NAME                              READY   STATUS    RESTARTS   AGE
bytebot-agent-xxxxx               1/1     Running   0          2m
bytebot-desktop-xxxxx             1/1     Running   0          2m
bytebot-postgresql-0              1/1     Running   0          2m
bytebot-ui-xxxxx                  1/1     Running   0          2m
```

## 故障排查

### Pod 未启动

查看 Pod 状态：
```bash
kubectl describe pod -n bytebot <pod-name>
```

常见问题：
- 资源不足：使用 `kubectl top nodes` 检查节点资源
- API Key 缺失：核对 `values.yaml` 配置

### 连接问题

测试服务连通性：
```bash
kubectl logs -n bytebot deployment/bytebot-agent
```

### 查看日志

```bash
# 查看所有日志
kubectl logs -n bytebot -l app=bytebot --tail=100

# 指定组件日志
kubectl logs -n bytebot deployment/bytebot-agent
```

## 升级

```bash
# 更新 values.yaml 后
helm upgrade bytebot ./helm -n bytebot -f values.yaml
```

## 卸载

```bash
# 移除 Bytebot
helm uninstall bytebot -n bytebot

# 清理命名空间
kubectl delete namespace bytebot
```

## 高级配置

<AccordionGroup>
  <Accordion title="使用外部 Secrets">
    如使用外部密钥管理（Vault、Sealed Secrets 等）：
    
    ```yaml
    bytebot-agent:
      apiKeys:
        anthropic:
          useExisting: true
          secretName: "my-api-keys"
          secretKey: "anthropic-key"
    ```
    
    手动创建 Secret：
    ```bash
    kubectl create secret generic my-api-keys \
      --namespace bytebot \
      --from-literal=anthropic-key="sk-ant-your-key"
    ```
  </Accordion>
  
  <Accordion title="LiteLLM 代理模式">
    如需集中管理 LLM，可使用内置 LiteLLM 代理：
    
    ```bash
    helm install bytebot ./helm \
      -f values-proxy.yaml \
      --namespace bytebot \
      --create-namespace \
      --set bytebot-llm-proxy.env.ANTHROPIC_API_KEY="your-key"
    ```
    
    该模式提供：
    - 集中化 API Key 管理
    - 请求路由与负载均衡
    - 限速与重试逻辑
  </Accordion>
  
  <Accordion title="自定义存储">
    配置持久化存储：
    
    ```yaml
    desktop:
      persistence:
        enabled: true
        size: "20Gi"
        storageClass: "fast-ssd"
    
    postgresql:
      persistence:
        size: "20Gi"
        storageClass: "fast-ssd"
    ```
  </Accordion>
</AccordionGroup>
